# SMS Switch v2.00.01 — Hotfix 2 (24 Aug 2026)

## Bugs found during full local simulation (your live DB dump restored, all functions exercised)

### 1. Web sending crashed with NULL delay (CRITICAL — affected your install)
`User::getDelay()` declared a non-nullable `: string` return but the `delay`
column is NULL in real databases. Any send from the dashboard/API threw:
`Return value must be of type string, null returned`.
**Fix:** `getDelay(): ?string`, `getUssdDelay(): ?int`, `getTimeZone(): ?string`.
File: `sms/model/User.php`

### 2. Android app never received messages (CRITICAL — why the APK "was not working")
The rewritten app polled `get-messages.php` directly with an empty `groupId`,
but the server assigns messages to *campaign groups* and only returns them
per-group (`get-campaigns.php` → `get-messages.php?groupId=…`). Result: the
app polled forever and sent nothing.
**Fix:** `SyncWorker` now follows the original protocol:
1. `get-campaigns.php` → list of pending campaign groupIds
2. `get-messages.php` per groupId → actual messages
3. send each message → `report-status.php`
Files: `android/.../SyncWorker.java`, `GatewayApi.java`, new
`GetCampaignsResponse.java`.

### 3. Wrong table name in device-auth group check
`includes/device_auth.php` queried table `messages`; the schema uses `Message`.
A groupId-protected poll would fatal instead of returning 401.
**Fix:** table name corrected.
